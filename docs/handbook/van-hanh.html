Trùng cổng 8090

Cả AVA và Gateway đều mặc định nghe AudioSocket ở 8090. Nếu chạy cả hai trên cùng host ở chế độ trực tiếp, hãy đổi một bên. AVA ở chế độ gateway không mở cổng này.

Dựng AVA

git clone <repo> && cd AVA-AI-Voice-Agent-for-Asterisk
sudo ./preflight.sh --apply-fixes          # tạo .env, sinh JWT_SECRET, căn quyền thư mục
docker compose -p asterisk-ai-voice-agent up -d --build --force-recreate admin_ui
docker compose -p asterisk-ai-voice-agent logs admin_ui | grep -i password   # mật khẩu một lần
# mở http://<host>:3003 và đi theo Setup Wizard
docker compose -p asterisk-ai-voice-agent up -d --build ai_engine
curl http://localhost:15000/health

Engine và local_ai_server mặc định dùng host networking để với tới Asterisk ở 127.0.0.1 và có độ trễ thấp. Có máy GPU thì dùng thêm lớp phủ docker-compose.gpu.yml.

Dialplan cho AVA

[from-ai-agent]
exten => s,1,NoOp(Asterisk AI Voice Agent)
 same => n,Set(AI_AGENT=sales-agent)
 same => n,Stasis(asterisk-ai-voice-agent)
 same => n,Hangup()

Sinh đoạn hiện hành bằng agent dialplan --agent <slug>.

Dựng Gateway

Yêu cầu: Asterisk 18+ có ARI, Stasis, chan_audiosocket và app_audiosocket; Python 3.12+ và Node.js 22+ để phát triển.

cp .env.example .env        # thay mọi giá trị giữ chỗ
docker compose build api admin-ui
docker compose up -d
docker compose ps
curl -fsS http://127.0.0.1:8080/api/v1/system/health
docker compose exec api alembic current

Vì sao giữ 8000 Hz

Trunk điện thoại là 8 kHz từ đầu đến cuối. Tăng tần số chỉ có lợi khi cả đầu cuối lẫn đối tác thật sự là băng rộng; nếu không, nó chỉ thêm một lần lấy mẫu lại ở mỗi ranh giới. Định dạng channel và tần số công bố được suy ra từ cùng một giá trị để không bao giờ lệch nhau.

Dialplan cho Gateway

[from-asterisk-ai-gateway]
exten => s,1,NoOp(Asterisk AI Gateway)
 same => n,Set(AI_GATEWAY_AGENT=support-agent)
 same => n,Stasis(asterisk-ai-gateway)
 same => n,Hangup()

[from-internal-custom]
exten => 9898,1,Goto(from-asterisk-ai-gateway,s,1)

Gateway tự tạo bridge và chân AudioSocket qua ARI. Không đặt URL đối tác, API key hay lệnh AudioSocket trong dialplan.

Truy cập dashboard

  • Mặc định bind loopback; truy cập qua đường hầm SSH: ssh -L 15173:127.0.0.1:15173 root@<gateway-host>.
  • Host pilot bind công khai ở cổng 15173 vì cổng 80/443 thuộc FreePBX.
  • Bind công khai qua HTTP thuần đưa cookie phiên lên đường truyền dạng rõ. Kết thúc TLS phía trước rồi bật GATEWAY_COOKIE_SECURE=true trước khi có lưu lượng tenant thật.

Kiểm chứng cuộc gọi đầu tiên

AVA

  1. agent check báo xanh.
  2. Gọi máy lẻ thử: lời chào → hai lượt hội thoại → tạm biệt.
  3. Xem Call History trong Admin UI.

Gateway

  1. ari show apps trên PBX liệt kê asterisk-ai-gateway.
  2. Chạy echo agent của SDK; nhận session.ready.
  3. Gọi máy lẻ thử: call.started → nghe lại giọng mình → call.ended.
  4. Gauge cuộc gọi và media đang hoạt động về 0 sau khi cúp.

Danh sách bàn giao cho đối tác

Thực hiện với đối tác trên một cuộc gọi thật:

  • Đổi token và đăng ký thành công.
  • Đối tác ghi log khối media nhận được và khớp với cấu hình triển khai.
  • Âm thanh hai chiều, người gọi xác nhận nghe rõ.
  • Mỗi lệnh được cấp chạy một lần; lệnh không được cấp trả command-denied và đối tác xử lý được.
  • Mọi đích sẽ dùng đều được allowlist chấp nhận.
  • Đối tác khởi động lại worker giữa cuộc gọi và thấy cuộc gọi kết thúc — để biết trước hành vi.

Sao lưu, khôi phục và sự cố

  • Gateway: pg_dump trước mỗi lần migration, đặt quyền 600. Khôi phục trong cửa sổ bảo trì sau khi dừng tiến trình ghi; quay lui bằng bản sao lưu và image cũ tương ứng, không chạy downgrade khi đang có ghi. Redis chỉ chứa lease tạm.
  • AVA: sao lưu thư mục data/ (hai tệp SQLite), config/ai-agent.local.yaml và .env.
  • Nghi lộ key: thu hồi key trên dashboard, cấp key thay thế, rà soát các lần đổi token.
  • Mất ARI: khôi phục kết nối riêng, rồi kiểm tra ari show apps và trạng thái sẵn sàng. Không khắc phục bằng cách mở ARI ra công khai hay chia sẻ thông tin PBX cho đối tác.
