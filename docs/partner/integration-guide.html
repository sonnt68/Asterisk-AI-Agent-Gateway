Tổng quanOverview

Gateway làm gì cho bạnWhat the gateway does for you

Gateway đứng giữa tổng đài Asterisk và AI agent của bạn. Nó giữ toàn bộ phần telephony — kênh thoại, bridge, ARI, chuyển mã âm thanh — ở phía trong, và chỉ phơi ra hai bề mặt công khai: một REST endpoint để đổi token, và một WebSocket realtime để nhận sự kiện, truyền audio hai chiều, và gửi lệnh điều khiển cuộc gọi. The gateway sits between the Asterisk PBX and your AI agent. It keeps all telephony — channels, bridges, ARI, audio transport — on its side of the boundary and exposes exactly two public surfaces: a REST endpoint that exchanges your key for a token, and a realtime WebSocket that carries events, bidirectional audio, and scoped call-control commands.

Xác thựcAuthentication

API key và token realtimeAPI keys and realtime tokens

API key là bí mật dài hạn, chỉ dùng cho đúng một việc: đổi lấy token realtime. Không bao giờ đặt API key lên query string, không log, không commit vào repo. The API key is a long-lived secret with exactly one job: exchanging it for a realtime token. Never put the key in a query string, a log line, or a repository.

HTTPPOST /api/v1/realtime/tokens
curl -X POST https://<gateway>/api/v1/realtime/tokens \
  -H "Authorization: Bearer agw_live_a1b2c3d4_e5f6…"

200 OK
{
  "token": "<short-lived realtime token>",
  "expires_in": "300"
}

Lưu ýWatch out

expires_in trả về dưới dạng chuỗi "300", không phải số. Hãy ép kiểu trước khi tính toán thời hạn.expires_in comes back as the string "300", not a number. Cast it before you do any expiry arithmetic.

Quy tắc vận hànhOperating rules

  • Token là dùng một lần cho mỗi kết nối. Mỗi lần kết nối lại phải xin token mới; không phát lại token cũ.One token per connection. Mint a fresh token on every reconnect; never replay an expired one.
  • Giới hạn tần suất. Mặc định 60 lần đổi token mỗi phút cho mỗi key. Vượt ngưỡng trả 429.Rate limit. 60 token exchanges per minute per key by default. Exceeding it returns 429.
  • Thu hồi có hiệu lực tức thì. Khi key bị thu hồi hoặc hết hạn, gateway chặn cả việc cấp token mới lẫn kết nối WebSocket mới.Revocation is immediate. A revoked or expired key blocks both token minting and new WebSocket sessions.
  • Xoay vòng key không có thời gian ân hạn. Lệnh rotate cấp key mới và thu hồi key cũ ngay lập tức.Rotation has no grace period. Rotating issues the replacement and revokes the old key at the same moment.

AudioAudio

Khung nhị phân: 16 byte UUID rồi tới PCMThe binary frame: 16 UUID bytes, then PCM

Audio đi theo cả hai chiều trên cùng WebSocket, dưới dạng khung nhị phân. Mỗi khung bắt đầu bằng 16 byte thô của call_id (UUID RFC 4122, dạng nhị phân — không phải chuỗi 36 ký tự), phần còn lại là audio thuần. Audio travels both directions on the same WebSocket as binary frames. Each frame opens with the 16 raw bytes of the call_id (an RFC 4122 UUID in binary form — not its 36-character string), and everything after that is raw audio.

call_id 16 byte thô của UUID16 raw UUID bytes
PCM s16le 16 kHz · mono · little-endian16 kHz · mono · little-endian
byte 0byte 15 byte 16byte N

Cùng một định dạng cho cả chiều gateway → partner và partner → gateway. SDK chính thức tự đóng và gỡ lớp bọc này; nếu tự dựng khung, ngoài 16 byte UUID đừng chèn thêm byte nào khác. The same layout in both directions. The official SDKs add and strip this envelope for you; if you frame by hand, never prepend anything beyond the 16 UUID bytes.

Điều kiện để khung audio được chấp nhậnWhat makes an audio frame valid

  • Bạn phải session.register thành công trước; gửi audio sớm hơn sẽ nhận protocol-invalid.You must have completed session.register; audio sent earlier returns protocol-invalid.
  • Khung phải dài hơn 16 byte. Khung chỉ có UUID mà không có audio bị từ chối với audio-invalid.The frame must be longer than 16 bytes. A UUID with no audio behind it is rejected with audio-invalid.
  • call_id phải thuộc một cuộc gọi đang hoạt động của chính kết nối này, nếu không sẽ nhận call-not-active.The call_id must belong to an active call owned by this connection, or you get call-not-active.
  • Nếu đường media phía Asterisk chưa sẵn sàng, gateway trả media-unavailable thay vì im lặng bỏ khung.If the Asterisk-side media path is not ready, the gateway answers media-unavailable rather than dropping the frame silently.

Chống trùng lặp bằng request_idIdempotency with request_id

Đặt một UUID vào request_id cho mọi lệnh bạn có thể phải gửi lại. Kết nối hiện tại ghi nhớ kết quả đã chấp nhận và trả lại đúng phản hồi cũ thay vì chạy lại hành động ARI lần thứ hai. Bộ nhớ này giữ 256 request gần nhất và mất khi kết nối đóng. Put a UUID in request_id on every command you might retry. The current connection remembers accepted results and replays the original response instead of running the ARI action twice. That memory holds the last 256 requests and is lost when the connection closes.

Allowlist đíchDestination allowlist

Mọi lệnh transfer.* (trừ transfer.cancel), route.* và outbound.originate đều phải có context và extension ghép thành chuỗi context:extension nằm chính xác trong allowlist của partner app. Không có wildcard, không có so khớp tiền tố. Every transfer.* (except transfer.cancel), route.*, and outbound.originate must carry a context and extension whose context:extension pair is exactly in your partner app's allowlist. No wildcards, no prefix matching.

  • context — 1–80 ký tự thuộc A–Z a–z 0–9 _ -context — 1–80 characters from A–Z a–z 0–9 _ -
  • extension — 1–80 ký tự thuộc A–Z a–z 0–9 * # + _ -extension — 1–80 characters from A–Z a–z 0–9 * # + _ -

Sai cú pháp hoặc không có trong allowlist đều trả command-denied. Đây là lỗi cấu hình, không phải lỗi tạm thời — thử lại không giúp ích. Bad syntax and a missing allowlist entry both return command-denied. That is a configuration error, not a transient one — retrying will not help.

Phát media và biến kênhPlayback and channel variables

Hai lệnh này chạm tới Asterisk bằng chuỗi do bạn chọn, nên gateway kiểm tra chặt và fail closed: cái gì không chứng minh được là an toàn thì bị từ chối trước khi ARI được gọi. These two hand Asterisk a string you chose, so the gateway validates hard and fails closed: anything not provably safe is refused before ARI is called.

  • media chỉ nhận sound:<tên> hoặc recording:<tên>. Các scheme khác như file: hay http: bị chặn vì sẽ đọc được file trên host qua ARI. Tên chỉ gồm A-Za-z0-9/_- và không được chứa ...media accepts only sound:<name> or recording:<name>. Schemes like file: or http: are refused because they would read host files through ARI. Names allow A-Za-z0-9/_- and may not contain ...
  • playback_id do gateway sinh và trả về trong result của call.control.accepted. Bạn chỉ dừng được playback của chính cuộc gọi mình sở hữu; mỗi cuộc gọi tối đa 8 playback đồng thời.The playback_id is minted by the gateway and returned in the result of call.control.accepted. You can only stop a playback your own call started; a call holds at most 8 concurrent playbacks.
  • Tên biến phải khớp AI_[A-Z0-9_]{1,60}. Tiền tố giữ bạn trong namespace riêng, và việc cấm ký tự ( chặn các hàm dialplan như CHANNEL(...), CDR(...), SHELL(...) — chúng thực thi chứ không phải gán giá trị.Variable names must match AI_[A-Z0-9_]{1,60}. The prefix keeps you in your own namespace, and rejecting ( blocks dialplan functions such as CHANNEL(...), CDR(...) and SHELL(...), which execute rather than assign.
  • Giá trị tối đa 512 ký tự, không chứa ký tự điều khiển.Values are capped at 512 characters and may not contain control characters.

Mã lỗi realtimeRealtime error codes

Lỗi luôn tới dưới dạng {"type":"error","code":…,"message":…} và không tự đóng kết nối. Hãy phân biệt lỗi cấu hình (không thử lại) với lỗi tạm thời (thử lại có backoff). Errors always arrive as {"type":"error","code":…,"message":…} and do not close the connection. Separate configuration errors, which you must not retry, from transient ones, which you should.

SDK

Mẫu tích hợpReference clients

SDK chính thức lo phần đổi token, đăng ký phiên, heartbeat 10 giây, kết nối lại kèm token mới, và đóng/gỡ khung audio. Mọi lệnh điều khiển đều có helper tương ứng và tự sinh request_id. Chỉ tự dựng khung thô khi môi trường của bạn không dùng được SDK. The official SDKs handle token exchange, registration, 10-second heartbeats, reconnect with a fresh token, and the audio envelope. Every control command has a helper that generates its own request_id. Hand-roll the raw framing only when your runtime cannot use an SDK.

async def on_event(event):
    if event["type"] == "call.started":
        print("call up:", event["call_id"])
    elif event["type"] == "error":
        print("denied:", event["code"], event["message"])
    elif event["type"] == "call.ended":
        print("call down:", event["call_id"])

async def on_audio(call_id, pcm):        # PCM s16le, 16 kHz, mono
    await client.send_audio(call_id, pcm)   # vọng âm / echo back

# Token, register, heartbeat và reconnect do SDK lo / handled by the SDK
asyncio.run(client.run(on_event=on_event, on_audio=on_audio))

Vận hànhOperations

Danh mục kiểm tra trước khi lên productionBefore you go live

  • API key nằm trong kho bí mật, được che khỏi log và thông báo lỗi.The API key lives in a secret store and is redacted from logs and error reports.
  • Mỗi lần kết nối lại đều xin token mới, có backoff luỹ tiến và giới hạn số lần thử.Every reconnect mints a fresh token, with exponential backoff and a retry ceiling.
  • Heartbeat 10 giây một lần, và bạn xử lý đúng các mã đóng 4401 / 1012 / 1013.Heartbeats go out every 10 seconds, and close codes 4401 / 1012 / 1013 are handled distinctly.
  • Mỗi call_id có đúng một chuỗi xử lý, và trạng thái được giải phóng khi call.ended.Exactly one handler chain per call_id, and state is released on call.ended.
  • Mọi lệnh có thể gửi lại đều mang request_id dạng UUID.Every retryable command carries a UUID request_id.
  • Chỉ một worker giữ mỗi agent_slug; kịch bản triển khai chờ cuộc gọi kết thúc trước khi tắt tiến trình cũ.One worker per agent_slug, and your deploy drains in-flight calls before the old process exits.
  • Bạn đã thử nghiệm với gateway thật và xác nhận allowlist đích đủ cho mọi luồng chuyển máy.You have tested against a real gateway and confirmed the allowlist covers every transfer path you use.

Giới hạn phạm viScope of this boundary

Đừng yêu cầu quyền truy cập ARI, SIP, AudioSocket, RTP, Docker hay máy chủ. Mọi thứ bạn cần đều nằm trong tài liệu này; nếu một tình huống không giải quyết được bằng các bề mặt trên, hãy trao đổi với bên vận hành gateway thay vì đi vòng qua biên bảo mật.Do not request ARI, SIP, AudioSocket, RTP, Docker, or host access. Everything you need is in this document; if a case cannot be solved with these surfaces, raise it with the gateway operator rather than routing around the boundary.
