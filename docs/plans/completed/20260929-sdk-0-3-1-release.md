## Outcome

Publish asterisk-ai-agent-gateway-sdk 0.3.1 on npm and PyPI with the validated
three-retry authentication fix.

## Context and scope

- Authority: user explicitly requested publication after the SDK retry change.
- Existing owner: .github/workflows/release-sdks.yml, triggered by sdk-v tags.
- Registry preflight: npm latest and PyPI latest both 0.3.0; prior release
  workflow succeeded. Reuse trusted publishing; no credentials in artifacts.
- Isolated checkout from 1e45f1a. Carry only SDK retry code, regression tests,
  package metadata and corresponding auth documentation. Exclude concurrent
  CMS/API, outbound examples, quotations and original staging.
- No server deployment, key rotation or application restart.

## Approach and risks

1. Bump both public packages and Node lockfile to 0.3.1.
2. Run repository and SDK checks; build and inspect wheel/sdist/npm archive.
3. Review release-only diff, commit, push source and wait for CI.
4. Push sdk-v0.3.1 through the existing trusted-publishing workflow.
5. Confirm workflow and both registry versions; install released artifacts
   in an isolated smoke-check environment.

Never overwrite a published version or force an existing tag. If one registry
fails, inspect the failed stage and recover only that side without republishing
different bytes under the same version. Preserve the primary dirty checkout.
